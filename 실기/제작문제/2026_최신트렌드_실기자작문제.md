## 📌 [단답형 영역] (각 3점)

### [문제 1] 제로 트러스트 아키텍처 (ZTA) 핵심 컴포넌트
다음은 미국 NIST SP 800-207에 정의된 제로 트러스트 아키텍처의 핵심 구성 요소에 대한 설명이다. 빈칸 (A)와 (B)에 들어갈 알맞은 구성 요소 명칭 또는 영문 약어를 쓰시오.

```text
- (  A  ) : 정책 엔진(Policy Engine)과 정책 관리자(Policy Administrator)로 구성되며, 
            주체의 신원, 단말 상태, 접근 대상 자원의 위험도 등을 종합 평가하여 
            접근 승인 여부를 최종 결정하는 논리적 컴포넌트.

- (  B  ) : 클라이언트와 엔터프라이즈 자원 사이의 데이터 경로에 위치하며, 
            ( A )의 결정에 따라 실제 네트워크 세션을 생성, 감시, 종료하는 
            게이트웨이 형태의 보안 시행 컴포넌트.
```
> **[모범 답안]**  
> * **(A):** 정책 결정 포인트 (PDP, Policy Decision Point)  
> * **(B):** 정책 시행 포인트 (PEP, Policy Enforcement Point)  
> * **[채점 기준 및 해설]:** 제로 트러스트 제어 평면(Control Plane)과 데이터 평면(Data Plane)을 분리하는 핵심 구조입니다. PDP와 PEP의 영문 약어 또는 한글 정식 명칭을 정확히 기재해야 정답으로 인정됩니다.

### [문제 2] 소프트웨어 공급망 보안 (Software Supply Chain Security)
소프트웨어 제품을 구성하는 오픈소스 패키지, 라이브러리 명칭, 버전, 라이선스, 디지털 서명, 공급자 정보 및 상호 의존 관계를 기계 판독 가능한 표준 형식(SPDX, CycloneDX 등)으로 목록화하여 공급망 투명성을 확보하고 Log4j와 같은 취약 컴포넌트를 조기에 식별·조치하기 위한 명세서의 공식 국문 명칭과 영문 약어를 쓰시오.

> **[모범 답안]**  
> * **정답:** 소프트웨어 자재명세서 (SBOM, Software Bill of Materials)  
> * **[채점 기준 및 해설]:** 국문 '소프트웨어 자재명세서' 또는 영문 약어 `SBOM` 모두 정답으로 인정됩니다.

### [문제 3] 생성형 AI 보안 취약점
대규모 언어 모델(LLM)을 기반으로 구축된 챗봇이나 AI 에이전트 서비스에서, 공격자가 교묘하게 조작된 프롬프트를 입력하여 모델에 내장된 시스템 지침(System Prompt)과 안전 가드레일을 무력화하고 인가되지 않은 명령을 수행하거나 기밀 데이터를 누출하도록 유도하는 최신 AI 보안 공격 기법의 명칭을 쓰시오.

> **[모범 답안]**  
> * **정답:** 프롬프트 인젝션 (Prompt Injection)  
> * **[채점 기준 및 해설]:** OWASP Top 10 for LLM의 제1순위 취약점(LLM01)으로, 직접 주입(Direct)과 외부 데이터 은닉(Indirect)을 포괄하는 공식 명칭입니다.

## 📌 [서술형 영역] (14점)

### [문제 4] 생성형 AI 간접 프롬프트 인젝션(Indirect Prompt Injection) 공격 원리 및 방어 대책
최근 기업 내부 문서나 웹 페이지를 검색하여 답변을 생성하는 RAG(검색 증강 생성) 기반 LLM 서비스가 확산되고 있다. 외부 공격자가 악의적인 외부 웹페이지나 PDF 문서를 검색 데이터 소스로 활용하여 시스템을 공격하는 **'간접 프롬프트 인젝션(Indirect Prompt Injection)'**에 대하여 다음 물음에 답하시오. (총 14점)

1. 간접 프롬프트 인젝션 공격이 성립하는 동작 메커니즘을 **'사전 준비 $\rightarrow$ 주입/트리거 $\rightarrow$ 피해 발생'의 3단계 인과관계**로 서술하시오. (6점)
2. 애플리케이션 및 시스템 계층에서 이를 원천 차단하기 위한 **보안 대책 2가지**를 구체적으로 기술하시오. (8점)

> **[모범 답안 및 채점 기준]**  
> 
> **1. 공격 동작 메커니즘 (6점 - 각 단계별 2점 부분점수):**
> * **(1단계 사전 준비):** 공격자는 웹 페이지, 이메일 본문, 공용 문서(PDF) 등 LLM이 참조할 수 있는 외부 데이터 소스 내에 사용자에게는 보이지 않는 은닉 텍스트(투명 폰트, HTML 주석, 프롬프트 탈취 명령 등) 형태로 악의적인 시스템 재정의 지시문을 삽입합니다.
> * **(2단계 주입 및 트리거):** 피해자가 정상적인 질의를 LLM에 요청하면, RAG 시스템이 해당 악성 외부 문서를 검색하여 컨텍스트(Context)로 LLM에 주입하게 되고, LLM은 데이터와 지시문을 구분하지 못하고 악성 지시문을 최우선 명령으로 해석하여 실행합니다.
> * **(3단계 피해 발생):** LLM은 피해자의 세션 권한을 이용해 내부 기밀 데이터를 외부 공격자의 서버로 유출(Data Exfiltration)하거나, 인가되지 않은 악의적인 시스템 도구(API)를 호출합니다.
> 
> **2. 보안 대책 2가지 (8점 - 항목당 4점 부분점수):**
> * **대책 1 (신뢰/비신뢰 데이터 분리 및 컨텍스트 격리):** LLM 프롬프트 구성 시 시스템 지침(System Instruction)과 외부 검색 데이터(User/Retrieved Data)를 명확한 구분자(XML 태그, JSON 구조체)로 격리하고, 외부 데이터 영역의 명령문은 텍스트 데이터로만 취급하도록 시스템 프롬프트를 강화합니다.
> * **대책 2 (출력값 검증 및 최소 권한 도구 호출):** LLM이 생성한 응답 텍스트를 백엔드 명령어나 웹 브라우저로 렌더링하기 전에 인젝션 탐지 가드레일(NeMo Guardrails, Llama Guard)로 2차 검증하며, LLM 에이전트가 호출할 수 있는 도구(Tool/Function Calling)에 엄격한 최소 권한(읽기 전용, 사용자 승인 필수)을 부여합니다.

## 📌 [실무형 영역] (14점)

### [문제 5] Docker 컨테이너 탈출 방지 보안 설정 및 iptables 무차별 대입 차단 룰셋 작성
클라우드 서버에서 운영 중인 웹 서비스 컨테이너 환경의 침해사고를 예방하기 위해 보안 설정을 수행하고자 한다. 다음 요구사항에 맞는 설정 명령어 및 규칙을 작성하시오. (총 14점)

#### [소문항 1] Docker 컨테이너 보안 기동 설정 (8점)
다음 3가지 보안 요구사항을 만족하도록 `docker run` 명령어를 완성하시오.
* 요구사항 1: 컨테이너 내부 프로세스가 추가적인 권한 상승(SetUID 등)을 시도하지 못하도록 차단할 것.
* 요구사항 2: 컨테이너의 루트 파일시스템을 읽기 전용(Read-only)으로 마운트하여 악성코드 쓰기를 방지할 것.
* 요구사항 3: 리눅스 기본 커널 기능(Capabilities)을 모두 제거(Drop)할 것.

```bash
docker run -d --name secure-web \
  [ (A) 요구사항 1 옵션 ] \
  [ (B) 요구사항 2 옵션 ] \
  [ (C) 요구사항 3 옵션 ] \
  nginx:alpine
```

#### [소문항 2] SSH 무차별 대입 공격(Brute Force) 방어 iptables 룰 작성 (6점)
동일한 출발지 IP에서 60초 동안 22번 포트(SSH)로 신규 연결(SYN) 요청이 5회 이상 발생할 경우, 해당 IP로부터의 접속 패킷을 폐기(DROP)하는 `iptables` 규칙 2줄을 작성하시오. (단, `recent` 모듈을 사용할 것).

```bash
# 규칙 1: 신규 접속 시도 IP를 SSH_ATTACK 목록에 등록
iptables -A INPUT -p tcp --dport 22 --syn -m recent --name SSH_ATTACK [ (D) 옵션 ]

# 규칙 2: 60초 이내에 5회 이상 재시도된 패킷 폐기
iptables -A INPUT -p tcp --dport 22 --syn -m recent --name SSH_ATTACK [ (E) 옵션 ] -j DROP
```

---

> **[모범 답안 및 채점 기준]**  
> 
> **[소문항 1 정답]:**
> * **(A) 요구사항 1:** `--security-opt no-new-privileges:true` (또는 `--security-opt=no-new-privileges`)
> * **(B) 요구사항 2:** `--read-only`
> * **(C) 요구사항 3:** `--cap-drop=ALL` (또는 `--cap-drop all`)
> 
> **[소문항 2 정답]:**
> * **(D) 옵션:** `--set`
> * **(E) 옵션:** `--update --seconds 60 --hitcount 5` (또는 `--rcheck --seconds 60 --hitcount 5`)
> 
> * **[채점 해설]:**  
>   1. `no-new-privileges` 플래그는 컨테이너 내에서 SetUID 바이너리 등을 악용한 권한 상승을 원천 차단하는 핵심 설정입니다.
>   2. `recent` 모듈에서 `--set`은 해당 패킷의 IP를 감시 테이블에 등록/갱신하며, `--update`는 등록된 시간과 횟수를 검사하여 지정된 임계치(`--seconds 60 --hitcount 5`)를 초과할 경우 DROP 조치합니다.
